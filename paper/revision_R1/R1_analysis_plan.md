# JRESS-D-26-05118, revision R1: pre-registered analysis plan

Version 1, 3 October 2026. This file is frozen by the git commit that adds it. Later changes are appended as dated amendments in Section 11 and never edit Sections 1 to 10. Every R1 result file records the SHA-256 of this file (`Experiments/r1_provenance.py`).

## 1. Principles

1. Test bearings are used only for the single final evaluation of configurations fixed by the rules below. Selection and development runs are started with `--skip-test` and do not load test bearings.
2. Every analysis specified here is reported, whatever its outcome. Failed or abandoned runs are listed in the experiment registry (Supplementary material).
3. The bearing is the unit of inference. Seed-level statistics describe sensitivity to initialization only.
4. Only training-bearing validation folds are used to choose between alternatives, by the rules stated here before the runs.

## 3. Our model: hyperparameter selection (Track A)

Common settings of every selection run: `--val-mode bearing --proportional-warmup --patience 999 --mc-passes 5 --pgmc-mode aux-seq --skip-test --save-val-preds --deterministic`. Score: final-epoch validation MAE. For a candidate setting s, m(s) is the mean of its 20 fold-seed scores and SE(s) their standard deviation divided by the square root of 20.

3.1 Budget: B in {5, 10, 20, 40}, argmin of m(B) (manuscript rule). Done: B* = 10 at lambda = 0.08 (`outputs/r1_lobo/selection_4fold.txt`).

3.2 Regularizer strength: lambda_PGMC in {0.08, 0.2, 0.5, 1.0, 2.0, 5.0} at B = 10, lambda_DANN fixed at 0.08 (as in the submitted sweep). Rule (manuscript Section 4.3, one-standard-error principle): keep lambda = 0.08 if m(0.08) <= min m + SE(argmin). Otherwise take the smallest lambda with m(lambda) <= min m + SE(argmin). Implemented in `Experiments/r1_select_lambda.py`.

3.3 If lambda changes, repeat 3.1 at the new lambda; if B then changes, repeat 3.2 once at the new B. Then retrain the final model (20 seeds) and all seven ablations at the selected (B, lambda) and rerun Sections 7 to 9. If lambda stays 0.08, the existing B = 10 final model and ablations stand.

3.4 Reproducibility check: the lambda = 0.08 runs of 3.2 repeat the existing B = 10 runs (`sweepseq_B10_fold{A,B,C,D}`), which used non-deterministic GPU kernels. Report the largest absolute difference in final-epoch validation MAE per run. Measured before registration: repeating the same non-deterministic run (fold C, seed 42, lambda = 0.08) gave final-epoch validation MAE 0.1489, 0.1455, 0.1448 and 0.1409; two deterministic repeats gave identical predictions and weights (maximum difference 0).

## 4. Calibration source (correction)

The submitted calibration (`exp22`, c* = 2.41) and the first R1 estimate (`r1_uq.py`, c* = 3.18) were fitted on the checkpoints saved by the selection runs. Those are best-validation checkpoints, chosen on the same bearing they are then calibrated on, while the deployed model is trained for a fixed budget and keeps its final epoch. This makes validation residuals optimistically small. From now on, calibration factors are fitted on final-epoch MC-dropout predictions (30 passes) of the Section 3 fold runs at the selected setting (`valpreds_seed*.npz`). The superseded values are reported with this reason. Selection runs still save best-validation checkpoints for backward compatibility; no analysis in this plan uses them.

## 5. Baselines: equal tuning effort

- Models: 1D CNN, BiLSTM, CNN-LSTM, 1D ResNet, Transformer, TSMC-CNN [21], MSCNN (Li et al. [7], Section 6).
- Budget selection with the same five selection seeds and four folds as our model, B in {5, 10, 20, 40} (MSCNN also 200, its published value); argmin of the 4-fold mean final-epoch validation MAE. Existing runs with seeds 42 and 123 are reused where their settings match; seeds 7, 777 and 999 are added with `--skip-test`.
- If a selected budget changes, that baseline is retrained with the 20 final seeds at the new budget, and the new result replaces the old one; the old one is reported as a sensitivity result.
- Each baseline keeps its implemented training settings; MSCNN and TSMC-CNN use their published settings.

## 6. MSCNN reproduction (Li, Zhang and Ding, RESS 182 (2019) 208-218)

- As published: horizontal channel; STFT with a 20 ms Hamming window (512 samples) and 10 ms shift (256); lower half of the frequency range (128 bins); 1 x 2 max-pooling along frequency; the 5 most recent recordings (N_hist = 5); per recording, three 3 x 3 convolutions with 5 filters whose outputs are concatenated, then a fourth 3 x 3 convolution with 5 filters; element-wise sum over the five recordings; a 3 x 3 convolution with 1 filter; a 128-unit fully connected layer; one sigmoid output; Leaky ReLU; dropout 0.5; zero padding; Xavier normal initialization; Adam, learning rate 1e-4 (constant), batch 32, MAE loss.
- Fixed by the protocol, as for every model: training bearings; whole-life labels (the paper's own "NoFPT" variant; onset-based labels define a different target); budget selection (Section 5); the common post-processing instead of the paper's onset-dependent smoothing; 20 final seeds.
- Not specified in the paper, chosen here: centred STFT frames (11 per recording, map 64 x 11); separate layers per recording (Fig. 2 indexes each recording's layers separately); Leaky ReLU slope 0.01; dropout after each of the four per-recording convolutions (Fig. 2); the history of the first four windows of a bearing filled by repeating its first recording; no input scaling.
- Smoke test (seed 42, fold A, 10 epochs, validation only). Pass: training loss decreases; standard deviation of validation predictions > 0.02; validation MAE below that of predicting the training-label mean. On failure, non-affine batch normalization of the STFT input (the TSMC-CNN remedy) is applied and the smoke test repeated once; both attempts are reported.
- Unit tests: output shapes; parameter count against a hand count; causality (the prediction for window t does not change when later windows change).
- A fidelity check under the authors' own protocol is not part of this plan.

## 7. Track B: pre-specified improvement candidates

Each candidate is accepted or rejected on validation folds only, tested once, and reported either way.

- B1. Seed ensembles, all models, post hoc. Point prediction: mean of member predictions. Predictive variance: mean of the members' MC-dropout variances plus the variance of the member means. Reported for every model as 5-member ensembles (the 20 final seeds in four disjoint groups of five, in seed-list order; metrics averaged over the groups) and as one 20-member ensemble. Single models remain the primary comparison. Ensemble calibration factors are fitted on 5-member validation ensembles from the Section 3 runs.
- B2. Temporal context for our model. The encoder is applied with shared weights to the K = 5 most recent windows, and their fused features are averaged before the regression head (no new parameters; K is taken from [7], not tuned). The variant goes through the full selection of Section 3 (budget sweep at lambda = 0.08, then the lambda rule). It replaces the current model only if its 4-fold validation mean at its selected setting is lower than the current model's (0.1510 at B = 10, lambda = 0.08, or the Section 3.3 result) by more than the current model's SE. If adopted: its ablations, XJTU-SY (Section 3 procedure on the XJTU folds) and Sections 8 to 9 are rerun, and the current model's results are reported as the submitted architecture's corrected results.
- B3. Stage-aware calibration. Separate two-sided scale factors for three bands of the predicted RUL mu: [0, 0.3), [0.3, 0.6), [0.6, 1]. Fitted like the global factor on the Section 4 validation predictions; first evaluated by leave-one-fold-out over the four folds (fit on three, evaluate on the fourth); then applied once to the test set. Reported next to the global factor whatever the result.
- B4. Causal smoothing strength. CES alpha in {0.05, 0.1, 0.2, 0.3, 0.5} with epsilon = 0.05, on the final-epoch validation predictions of the Section 3 runs. Keep alpha = 0.2 unless another value lowers the 4-fold validation CES MAE by more than one SE; then take the argmin.

## 8. Statistics

- Primary endpoint: bearing-averaged CES MAE on all10, our model against each of the seven baselines. Exact two-sided sign-flip permutation test on the per-bearing differences of seed-mean MAE (all 2^n sign patterns); Holm adjustment across the seven baselines; alpha = 0.05; reported with the number of bearings on which each model is better.
- Co-reported for the same comparisons: raw MAE; window-pooled MAE, RMSE and R^2; PAVA, labelled offline.
- Secondary families, each Holm-adjusted within itself: ablations (seven variants against the full model); protocol demonstrations (in-bearing early stopping; lambda chosen by validation argmin).
- orig4, new6 and zs3 are reported descriptively with the same tests, each with its smallest attainable p-value (2 / 2^n).
- Seed-level paired tests are reported only as sensitivity to initialization.
- Software: `Experiments/r1_strict_stats.py`, extended to these families.

## 9. Uncertainty and decisions

- Calibration (Section 4 source): global two-sided factor c* and one-sided factor k*; two-sided coverage and one-sided lower-bound coverage on all10, per bearing and per true-RUL band [0, 0.2), [0.2, 0.5), [0.5, 1].
- Decisions (`Experiments/r1_decision.py`): alarm rates at tau = 0.20; alarm timing at tau in {0.30, 0.20, 0.10}; closed-form break-even cost ratios; and the number of bearings (majority over seeds) on which each rule triggers late.

## 10. Reproducibility and reporting

- All runs started under this plan use deterministic CUDA kernels (`--deterministic`), so a seed reproduces a run exactly. Runs made before this plan (final model, ablations, baselines, budget sweeps) used non-deterministic kernels; their saved checkpoints reproduce every reported number on re-evaluation, and retraining them reproduces those numbers only up to the spread quantified in Section 3.4. They are not retrained unless a rule in this plan requires it.
- Every R1 result file records: SHA-256 of this plan and of the code files used, git commit and whether the working tree differs, command line, Python, PyTorch, CUDA, NumPy and SciPy versions, GPU, and the data fingerprints of Section 2.
- Environment at registration: Python 3.14.3, PyTorch 2.11.0+cu128 (CUDA 12.8), NumPy 2.4.4, SciPy 1.17.1, NVIDIA GeForce RTX 5070. Parent commit b1762d638840f4a10da7c9cfefd0f002b4bfb980.
- Manuscript tables and in-text numbers are generated by script from the result files and checked against the manuscript before submission.
- Experiment registry: every run, including failed and abandoned ones, with purpose and outcome.
- Order of work: Section 3.2 first (it can change our model); then Sections 5, 6 and 7 (B2 validation stage) in parallel; then Sections 4, 7 (B1, B3, B4), 8 and 9.
